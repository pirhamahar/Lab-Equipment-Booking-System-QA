### 4. Defect Classification

**Severity:**
- Critical: Causes system failure or prevents essential functionality.
- High: Major functionality does not work correctly.
- Medium: A feature works incorrectly but does not prevent overall system operation.
- Low: Minor issue with limited impact.

**Priority:**
- High: Requires immediate correction.
- Medium: Should be corrected in the next development cycle.
- Low: Can be addressed later.

### 5. Defect Lifecycle

1. Identification: A defect is discovered during testing.
2. Reporting: The defect is recorded in the Defect Log.
3. Classification: Severity and priority are assigned.
4. Assignment: The defect is assigned for correction.
5. Correction: The developer fixes the defect.
6. Retesting: The corrected functionality is tested again.
7. Closure: The defect is closed after successful retesting.
